name: release-notes-from-history
description: Use this when asked to prepare changelogs, release notes, or project updates for this repository from commits, pull requests, issues, or other recorded history.
---

When drafting release notes, changelogs, or project updates:

1. **Source of Truth**: Gather facts exclusively using repository evidence (such as git commit history, pull requests, and issues) instead of inferring features.
2. **Substantiated Claims**: If a change cannot be substantiated by git or repository records, do not present it as fact.
3. **Outcome-Oriented**: Write concise, user-visible summaries and group them by user-visible outcomes when possible.
4. **Planned vs. Shipped**: Clearly distinguish and separate shipped work from planned/unreleased work. Keep unreleased areas marked as placeholders.
5. **Structural Consistency**: Keep the release notes layout and format compatible with both the website pages and the Starlight documentation/changelog structure in the repository.
